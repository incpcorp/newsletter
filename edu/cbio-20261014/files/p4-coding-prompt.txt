■ 코딩 프롬프트 카드 D (강사 시연 · 3개 모델 공용)
아래 URS-DEVLOG-001의 모든 요구사항(FR·DR·TR·NF)을 구현하는 교육용 단일 HTML 파일을 작성하라.
코드를 쓰기 전에 ① 요구사항을 ID별로 한 줄씩 요약하고 ② 해석이 모호한 요구와 네가 가정한 내용을 표로 제시하라.
제약: 외부 라이브러리·CDN·네트워크 요청·localStorage·쿠키 사용 금지. 사용자 입력은 textContent로만 화면에 표시. 수정 이력의 시각은 시스템 시계로만 기록.
출력: ① 완성 코드 1개 ② 요구사항 ID → 구현 위치(함수명) 대응표 ③ 요구사항별 수동 시험 방법.
금지: 'GMP 적합', '밸리데이션 완료' 표시. 내가 수행하지 않은 시험을 '합격'으로 기재하지 말 것.

---------------- URS 본문 (이 아래 전체를 함께 붙여넣기) ----------------
URS-DEVLOG-001 v1.0 — 교육용 일탈 접수·기한관리 대장 (DEV-LOG) 사용자 요구사항 규격서
1. 목적: 일탈 최초 접수 정보를 입력할 때 필수항목·일시 형식·시간 순서를 점검하고, SOP(QA-SOP-008, 실습3 S3-4)에 정한 보고 기한(인지 후 24시간)과 조사 완료 기한(중대 30일·경미 15일)을 자동 계산하며, 등록 기록의 수정 이력을 남겨 접수 단계의 누락과 계산 실수를 줄인다.
2. 범위 외: 일탈 등급의 판정, 근본원인 판단, 승인·전자서명, 사용자 인증, 데이터의 영구 저장·백업은 범위에서 제외한다(교육용 단순화 — 6.7 제약사항 참조).
3. 분류: GAMP 5 소프트웨어 카테고리 5 (자체 개발, AI 코딩 도구로 작성한 결정론적 코드 — 실행 중 AI를 호출하지 않음)

[6.1 기능 요구사항]
FR-01 (M) 시스템은 일탈번호, 제목, 제품명, 배치번호, 발생일시, 인지일시, 보고일시, 등급(중대/경미 중 선택), 보고자, 내용의 10개 항목을 입력받아야 한다.
FR-02 (M) 시스템은 10개 항목의 앞뒤 공백을 제거한 뒤 빈 값이면 등록을 차단하고 “[항목명]: 누락”을 표시해야 한다.
FR-03 (M) 시스템은 일탈번호가 DEV-YYYY-NNN(숫자 4자리-숫자 3자리) 형식이 아니면 등록을 차단하고 “일탈번호: 형식 오류 (DEV-YYYY-NNN)”를 표시해야 한다.
FR-04 (M) 시스템은 발생·인지·보고일시가 YYYY-MM-DD HH:MM 형식이 아니면 “[항목명]: 형식 오류 (YYYY-MM-DD HH:MM)”를, 실제 존재하지 않는 날짜·시각(예: 2026-02-29, 24:30)이면 “[항목명]: 존재하지 않는 날짜·시각”을 표시하고 등록을 차단해야 한다.
FR-05 (M) 시스템은 발생일시 ≤ 인지일시 ≤ 보고일시가 아니면 등록을 차단하고 “시간 순서 오류: 발생일시 ≤ 인지일시 ≤ 보고일시”를 표시해야 한다.
FR-06 (M) 시스템은 보고 기한을 ‘인지일시 + 24시간’으로 계산하여, 보고일시가 기한과 같거나 이전이면 “준수”, 기한을 넘으면 “지연 (초과 HH:MM)”을 표시해야 한다. 지연은 등록을 차단하지 않는다.
FR-07 (M) 시스템은 조사 완료 기한을 인지일(날짜) 기준 달력일로 중대 +30일, 경미 +15일 계산하여 YYYY-MM-DD로 표시해야 한다.
FR-08 (M) 시스템은 FR-02~FR-05 및 FR-10의 오류가 하나라도 있으면 등록을 차단하고 발견된 오류를 모두 목록으로 표시해야 한다. 오류가 없으면 대장에 추가해야 한다.
FR-09 (M) 시스템은 등록된 기록을 대장 표(일탈번호, 제목, 제품/배치, 등급, 인지일시, 보고 기한, 조사 완료 기한)로 표시해야 한다.
FR-10 (M) 시스템은 이미 등록된 일탈번호와 같은 번호의 등록을 차단하고 “일탈번호: 중복 (이미 등록됨)”을 표시해야 한다.
FR-11 (M) 시스템은 등록된 기록의 제목·제품명·배치번호·등급·보고자·내용을 수정할 수 있어야 하며, 수정 사유의 앞뒤 공백을 제거한 값이 비어 있으면 수정을 차단하고 “수정 사유: 누락”을 표시해야 한다. (일탈번호와 일시 항목은 수정 대상에서 제외)
FR-12 (M) 시스템은 수정이 저장될 때마다 기록 시각(시스템 시계, YYYY-MM-DD HH:MM:SS), 일탈번호, 항목명, 변경 전 값, 변경 후 값, 수정 사유를 수정 이력 표에 자동으로 추가해야 한다. 등급이 수정되면 조사 완료 기한을 다시 계산해야 한다.
FR-13 (M) 시스템은 등록 기록과 수정 이력을 삭제하거나 편집하는 기능을 제공하지 않아야 한다.

[6.2 데이터 요구사항]
DR-01 (M) 시스템은 사용자 입력을 화면에 텍스트로만 표시해야 하며, HTML로 해석하거나 스크립트로 실행해서는 안 된다.
DR-02 (M) 수정 이력의 기록 시각은 시스템이 자동으로 부여해야 하며, 사용자가 입력하거나 변경할 수 없어야 한다.
DR-03 (M) 시스템은 데이터가 저장되지 않으며 새로고침하면 사라진다는 안내를 화면에 표시해야 한다.

[6.3 기술 요구사항]
